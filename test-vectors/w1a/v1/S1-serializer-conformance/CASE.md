# S1 — serializer conformance

| | |
|---|---|
| Case ID | `S1-serializer-conformance` |
| Purpose | Force the canonical serializer and a naive one to **diverge**, so `NORM-035` is certified |
| Requirement certified | `NORM-035` (escape alphabet, key ordering, trailing LF) |
| Positive / negative | **positive** — the canonical serializer must reproduce `expected/canonical.bytes` exactly |
| Expected rejection stage | n/a |
| Why it exists | Every host-derived case is ASCII `[0-9a-z:/.-]`, so a serializer that emits DEL, C1 and U+2028/9 **raw** reproduced the entire corpus identically. This case isolates serialization from collection: it has **no host input**. |

`expected/canonical.bytes` is **hand-written and reviewable**, not generated by the serializer under test.
That is what breaks the circularity: equality with a generated file would prove nothing.

## The divergence, byte for byte

| Code point | Canonical (`NORM-035`) | Naive `ensure_ascii=False` |
|---|---|---|
| U+007F DEL | `\u007f` | raw `7f` |
| U+0085 (C1) | `\u0085` | raw `c2 85` |
| U+2028 | `\u2028` | raw `e2 80 a8` |
| U+2029 | `\u2029` | raw `e2 80 a9` |

Key ordering is by **Unicode code point**, so `k` (U+006B) < U+FFFD < U+10000. An implementer sorting by
UTF-16 code unit would place U+10000 (surrogate `d800`) **before** U+FFFD and fail this case.

`é`, `/` and the astral character stay raw: `NORM-035` escapes exactly the listed rows and nothing else.
