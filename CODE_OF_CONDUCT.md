# Code of Conduct

Status: IMPLEMENTED

ISEDRAF is a security trust tool. The work depends on people being able to say plainly that something is
wrong — a result is false, a claim is overstated, a limitation is not documented. This policy exists to
keep that possible.

## Expected conduct

- **Be precise.** Disagree with the evidence, the reasoning or the code. Cite a path, a command output or
  a requirement ID.
- **Be direct without being personal.** "This reports PASS for a control it never collected" is useful.
  An assessment of the person who wrote it is not.
- **Assume competence.** Contributors come from system administration, security engineering and audit
  backgrounds. Each sees a different part of the problem.
- **Accept correction.** Being wrong about a technical claim is ordinary and carries no stigma here. Being
  unwilling to check is the problem.
- **Respect privacy.** Never publish another person's host data, identity information or infrastructure
  details. Redact before sharing.

## Unacceptable conduct

- Personal attacks, insults, or demeaning comments about a person rather than their work.
- Harassment of any kind, including unwanted contact after being asked to stop.
- Discriminatory language or conduct based on personal characteristics.
- Publishing private information — anyone's — without explicit permission.
- Deliberately filing false or misleading reports, or misrepresenting what ISEDRAF observed.
- Pressuring a maintainer to weaken a security gate, a test or a documented limitation.

## Scope

This policy applies in all project spaces — issues, pull requests, discussions, commit messages, code
comments and documentation — and to any conduct elsewhere that directly affects the project or its
contributors.

## Reporting

Report concerns privately to **`contact@itcms.gr`**.

Reports are read by the project owner. You will receive an acknowledgement. Reports are kept confidential;
details are shared only as far as necessary to act on them. You may report conduct that affects someone
else.

Do not use a public issue to raise a conduct concern about a named person.

## Enforcement

The project owner decides and is accountable for the outcome. Responses are proportionate and may include
a private clarification, a request to edit or withdraw a comment, a warning, or removal from the project's
spaces. Anyone acting on a report will say so plainly rather than resolving it silently.

Enforcement decisions are about conduct, never about the technical position someone held.

## A note on authorship

This policy is written for ISEDRAF. It is not adapted from another project's text. If you prefer a
recognized external standard for your own work, that is a reasonable choice — this project simply states
its own expectations in its own words.
